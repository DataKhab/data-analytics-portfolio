# Recipe Recommendation System

Проект по исследовательскому анализу данных (EDA)
датасета рецептов и пользовательских взаимодействий Food.com
(источник: Kaggle, датасет *Food.com Recipes and Interactions*).

Цель проекта — продемонстрировать полный цикл работы аналитика:

- подготовка окружения и воспроизводимость;
- загрузка и предобработка «тяжёлых» данных (архив > 100 МБ, разбитый на части);
- исследовательский анализ данных (EDA) для таблиц рецептов,
  взаимодействий и подготовленных признаков;
- визуализация ключевых метрик (распределения, корреляции, диаграммы рассеяния);
- формулировка выводов и рекомендаций для задачи построения рекомендательной системы.

---

## 1. Бизнес-задача

Сервис рецептов Food.com хранит:

- **231 637** рецептов (`RAW_recipes.csv`);
- **1 132 367** пользовательских взаимодействий (`RAW_interactions.csv`);
- подготовленные обучающую, тестовую и валидационную выборки
  для задачи рекомендаций (`PP_recipes.csv`, `PP_users.csv`,
  `interactions_train.csv`, `interactions_test.csv`,
  `interactions_validation.csv`);
- словарь ингредиентов `ingr_map.pkl`.

Задача — исследовать структуру данных и понять, какие признаки
и закономерности стоит учитывать при построении рекомендательной
системы «пользователь → рецепт».

## 2. Данные

Файлы данных находятся в папке `data/`.

> Файл `recipes.zip` превышает 100 МБ и не хранится в репозитории в одном файле.
> Он разбит программой 7-Zip на части `recipes.zip.001`, `recipes.zip.002`,
> `recipes.zip.003`. Перед запуском ноутбука архив нужно склеить и распаковать.

Распаковка на Windows:

1. Скачайте все три части `recipes.zip.001`, `recipes.zip.002`, `recipes.zip.003`
   в одну папку `data/`.
2. Правой кнопкой мыши на `recipes.zip.001` → **7-Zip → Extract Here**.
3. В папке `data/` появятся CSV-файлы и `ingr_map.pkl`.

Полное описание файлов — в `data/README_data.md`.

6. Ключевые выводы
Пропуски. В RAW_recipes.csv отсутствуют описания у ≈ 2,15 % рецептов
(4 979 записей) и одно пустое значение в колонке name.
В RAW_interactions.csv — 169 пустых отзывов (0,015 %).
Остальные таблицы заполнены полностью.

Выбросы. По количеству шагов и количеству ингредиентов
наблюдаются рецепты, резко выделяющиеся из общей массы
(максимум — 43 ингредиента и 145 шагов). Это потенциальные
кандидаты на фильтрацию или отдельный анализ.

Корреляции. В RAW_recipes.csv наблюдается заметная
корреляция между числом шагов и числом ингредиентов (≈ 0,43),
что логично: сложные рецепты содержат и больше ингредиентов,
и больше шагов.

Рейтинги. Распределение оценок сильно смещено
в сторону максимальной оценки 5 — это классическая
проблема смещения пользовательских оценок, которую необходимо
учитывать при построении рекомендательной системы
(например, нормализовать рейтинги по пользователю).

Популярность. Топ-10 рецептов по количеству отзывов
хорошо демонстрируют, что популярность распределена по «длинному хвосту» —
небольшая доля рецептов собирает основную часть отзывов.

Ингредиенты. Частотный анализ ингредиентов даёт основу
для content-based рекомендаций: можно рекомендовать рецепты
с похожим набором ингредиентов.

7. Рекомендации для построения рекомендательной системы
Использовать гибридную схему: коллаборативная фильтрация
(по user_id и recipe_id) + content-based признаки
(инградиенты, теги, количество шагов).

Нормализовать рейтинги по каждому пользователю,
чтобы компенсировать смещение оценок к 5.

Исключать или отдельно обрабатывать рецепты-выбросы
(с очень большим числом шагов/ингредиентов).

Для холодного старта пользователей опираться на content-based
признаки (топ ингредиентов, категории блюд).

Кэшировать предобработанные таблицы (parquet / duckdb),
чтобы не распаковывать архив при каждом запуске.
